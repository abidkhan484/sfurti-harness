# Domain docs

This project uses a single context.

Before exploring or changing the project:
- Read the root `CONTEXT.md`.
- Read decisions in `docs/adr/` relevant to the work.

Use glossary vocabulary in specs, issues, code, and tests.
Surface conflicts with existing ADRs rather than silently overriding them.

Keep `CONTEXT.md` a glossary. Record architectural decisions in ADRs.
If domain documents are absent, proceed without creating placeholders;
domain-modeling creates them when terms or decisions are resolved.
